Unofficial Flatpak package

ChatGPT and Codex on any Linux with Flatpak

OpenAI ships the ChatGPT desktop client for Linux only as an RPM. This project repackages it as a Flatpak and hosts it in an automatically updated, signed repository, so Fedora Atomic, Bazzite, SteamOS, Debian, Ubuntu, and similar systems can install it directly.

Install

Once the remote is added, ChatGPT updates with flatpak update.

shell 
flatpak remote-add --if-not-exists chatgpt https://jhuang6451.github.io/chatgpt-flatpak/chatgpt.flatpakrepo
flatpak install chatgpt com.openai.chatgpt
flatpak run com.openai.chatgpt

The runtime comes from Flathub. If Flathub isn't enabled yet, run flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo first. Installing from the .flatpakref works without this step because the file includes the Flathub URL.

The repository is signed with GPG. .flatpakrepo and .flatpakref embed the public key, and Flatpak verifies signatures automatically. Key fingerprint: 5F01 B1FD 3DD6 D620 2FA9 0276 B82A 2266 6F3D EC39. If you added the chatgpt remote before signing was enabled, run flatpak remote-delete chatgpt and add it again.

What's in the package

The build downloads the RPM from OpenAI's YUM repository, checks the SHA-256 recorded in the manifest, and unpacks it. The one change to upstream code is a pair of patches in the bundled codex binary, described below.

Official source

The download URL and hash are in the manifest and change with each version commit, so you can check them in the repository.

Automatic updates

GitHub Actions reads OpenAI's repository index every 6 hours. When a new version appears, it updates the manifest, builds, and publishes.

Codex commands

Codex can run shell commands inside Flatpak. CI runs a command through the Codex sandbox after every build.

Wayland and keyring

Wayland sessions get Ozone and window decorations automatically. Login state is stored in GNOME Keyring or KDE Wallet.

How Codex runs inside Flatpak

Codex runs each command through bubblewrap. Flatpak is already a bubblewrap sandbox and blocks nested user namespaces, and Codex also rejects Flatpak's /run/.userns mount with mountinfo path is not absolute. The build handles this in three steps:

  1. Patch two checks. patch-codex.py disables the mount-root check and the SHA-256 check on the bundled bubblewrap. Each patch must match exactly one location, or the build fails.
  2. Replace bubblewrap with a shim. bwrap_shim.c applies --chdir, --setenv, and similar options, ignores mount and namespace options, and runs the command.
  3. Check every build. CI runs codex sandbox in the built package and fails if either patched error comes back.

The shim doesn't create a sandbox, so Codex's filesystem restrictions are not enforced: commands can write anywhere in your home directory, even in read-only mode. Network restriction still works, because Codex applies it with seccomp.

Permissions

ChatGPT and every command Codex runs can read and write your whole home directory. The app can't run commands on the host.

PermissionPurpose
--filesystem=homeRead and write the home directory, so Codex can work on local projects
--share=networkChatGPT and Codex services
--device=driGPU acceleration
Wayland, X11, PulseAudioDisplay, audio, and voice
Notifications, tray, keyringDesktop integration and login storage

To limit access to one project directory, use Flatseal or this command:

shell 
flatpak override --user --nofilesystem=home --filesystem=~/Projects com.openai.chatgpt

Known limitations

  • x86_64 only. OpenAI publishes only x86_64 RPMs.
  • Codex filesystem sandboxing is not enforced. Network restriction still works.
  • Few developer tools inside the sandbox. The runtime has python3 and curl, but no git, node, gcc, or make. To use host tools, grant --talk-name=org.freedesktop.Flatpak and call them through flatpak-spawn --host, which gives the app full access to your account.
  • New upstream versions can break the patches. The build then fails and the repository stays on the previous version until the patterns are updated.

How updates work

Each release is built from an empty repository, so the remote keeps only the latest commit. OSTree addresses files by content and clients download only the objects they lack, but there are no deltas from older versions.
