非官方 Flatpak 打包

在任何支持 Flatpak 的 Linux 上使用 ChatGPT 和 Codex

OpenAI 只提供 RPM 格式的 ChatGPT Linux 客户端。这个项目把它重新打成 Flatpak,放进一个自动更新、带签名的软件源,让 Fedora Atomic、Bazzite、SteamOS、Debian、Ubuntu 等系统也能直接安装。

下载 .flatpakref 用命令行安装 离线包

仅提供 x86_64。本项目与 OpenAI 没有隶属关系。

安装

添加软件源后,ChatGPT 会随 flatpak update 一起更新。

shell 
flatpak remote-add --if-not-exists chatgpt https://jhuang6451.github.io/chatgpt-flatpak/chatgpt.flatpakrepo
flatpak install chatgpt com.openai.chatgpt
flatpak run com.openai.chatgpt

应用的 Runtime 来自 Flathub。如果系统还没有启用 Flathub,先执行 flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo。用 .flatpakref 安装时,Flathub 的地址已经包含在文件里。

软件源已用 GPG 签名,.flatpakrepo 和 .flatpakref 内嵌了公钥,Flatpak 会自动校验。签名密钥指纹:5F01 B1FD 3DD6 D620 2FA9 0276 B82A 2266 6F3D EC39。如果你在启用签名之前添加过 chatgpt 软件源,请先执行 flatpak remote-delete chatgpt 再重新添加。

打包内容

构建时从 OpenAI 的 YUM 源下载 RPM,核对清单里记录的 SHA-256,再解包。对上游代码唯一的改动是自带 codex 二进制里的两处补丁,下文有说明。

官方来源

下载地址和哈希写在清单中,每次版本变化都会随提交更新,可以在仓库里逐条核对。

自动跟进

GitHub Actions 每 6 小时读取一次 OpenAI 的软件源索引,发现新版本就更新清单、构建并发布。

Codex 命令

Codex 能在 Flatpak 里执行 shell 命令。每次构建后,持续集成都会通过 Codex 沙箱实际运行一条命令。

Wayland 与密钥环

Wayland 会话自动启用 Ozone 和窗口装饰。登录状态保存在 GNOME Keyring 或 KDE Wallet 中。

Codex 在 Flatpak 中如何运行

Codex 通过 bubblewrap 执行每条命令。Flatpak 本身就是 bubblewrap 沙箱,禁止嵌套 user namespace;Codex 还会因为 Flatpak 的 /run/.userns 挂载报 mountinfo path is not absolute。构建分三步处理:

  1. 修补两处检查。patch-codex.py 关闭挂载根检查和对自带 bubblewrap 的 SHA-256 校验。每个补丁必须恰好匹配一处,否则构建失败。
  2. 用垫片替代 bubblewrap。bwrap_shim.c 处理 --chdir、--setenv 等参数,忽略挂载和命名空间参数,然后执行命令。
  3. 每次构建都检查。持续集成在构建好的包里运行 codex sandbox,如果再次出现被修补的错误,构建失败。

垫片不创建沙箱,Codex 的文件系统限制不生效:即使在只读模式下,命令也能写入用户目录的任何位置。网络限制仍然有效,因为 Codex 用 seccomp 实现它。

权限

ChatGPT 和 Codex 执行的每条命令都能读写整个用户目录。应用不能在宿主系统上执行命令。

权限用途
--filesystem=home读写用户目录,供 Codex 处理本地项目
--share=network访问 ChatGPT 和 Codex 服务
--device=driGPU 加速
Wayland、X11、PulseAudio显示、音频和语音
通知、托盘、密钥环桌面集成与登录状态保存

想只开放一个项目目录,可以用 Flatseal 或下面的命令:

shell 
flatpak override --user --nofilesystem=home --filesystem=~/Projects com.openai.chatgpt

已知限制

  • 仅 x86_64。OpenAI 只发布 x86_64 的 RPM。
  • Codex 的文件系统沙箱不生效。网络限制仍然有效。
  • 沙箱里的开发工具很少。Runtime 里有 python3 和 curl,没有 git、node、gcc、make。要使用宿主工具,可以授予 --talk-name=org.freedesktop.Flatpak 并通过 flatpak-spawn --host 调用,这样应用会拥有你账户的全部权限。
  • 上游新版本可能让补丁失效。这时构建会失败,软件源停在上一个版本,直到补丁模式更新。

更新方式

每次发布都从空仓库重新构建,软件源只保留最新提交。OSTree 按内容寻址,客户端只下载本地缺少的对象,但没有从旧版本出发的增量包。
